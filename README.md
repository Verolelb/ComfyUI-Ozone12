# ComfyUI-Ozone12

Hosts **iZotope Ozone 12 VST3 plugins** headlessly inside ComfyUI and applies
them to audio, using [pedalboard](https://github.com/spotify/pedalboard)
(Spotify's JUCE-based audio library, already installed in ComfyUI's embedded
Python).

The plugins are the real `Ozone 12 *.vst3` files from
`C:\Program Files\Common Files\VST3\iZotope` — no reimplementation, full DSP.

## Nodes

### Per-module nodes with real widgets (category `audio/vst/ozone`)

One node per Ozone module (20 nodes), each with **real sliders and toggles**
auto-generated from the plugin's actual parameters (ranges, steps, units,
defaults read from the plugin itself):

- `Ozone 12 Maximizer` — input/output gain, character, bypass toggles…
- `Ozone 12 Dynamics` — per-band threshold, ratio, attack/release…
- `Ozone 12 EQ` / `Ozone 12 Dynamic EQ`, Vintage Tape, Exciter, Imager…

Each node also has a **`preset` dropdown** listing the Ozone presets found on
this machine (factory presets from `C:\Program Files\iZotope\Ozone 12\Presets`
and your user presets from `Documents\iZotope\Ozone\User Presets` — save a
preset in the Ozone app and it appears here after a ComfyUI restart), plus a
**`Preset On` toggle**:

- **`Preset On` = ON** → the selected preset takes over; your manual slider/
toggle settings are ignored.
- **`Preset On` = OFF** → your manual settings apply and the preset is
  ignored entirely.
- With **`Preset On` ON but no preset selected**, the node falls back to your
  manual settings.

Outputs: processed `audio` and an `info` JSON summary (preset applied,
params applied, warnings).

### Ozone Global Mastering (`OzoneGlobalMastering`)

Applies a full mastering-chain (global) preset from Ozone's Preset Manager
(All Purpose Mastering, Expert Curated Presets, Genre-Specific Mastering,
Mix Bus, Ozone Legacy, Stem Focus). Each enabled module of the preset is
applied through its standalone plugin, chained in master order
(EQ -> dynamics -> limiter). The full `Ozone 12.vst3` can't host the chain
headlessly (its rack state is not exposed as parameters), so each enabled
module section runs through its standalone plugin.

- **`Amount` (0-100%)**: parallel wet/dry mix of the preset — 100% = full
  preset, 0% = dry. The chain measured 0 samples of latency, so the blend
  is phase-clean (verified: 50% equals exactly 0.5×dry + 0.5×wet).
- **Modules actifs**: after each run, the node shows the modules the preset
  enabled with their **measured effect** on your actual audio (green =
  audible Δ dB, amber = subtle, grey = enabled but left at defaults). The
  measurement is live — each module's Δ RMS / Δ crest is computed on your
  own audio while the chain runs (no extra processing).
- **Preset dropdown badges**: every preset is tagged with its measured type
  ([VOL] / [TONE] / [DYN] / [FULL]) and RMS change in dB (from
  `preset_types.json`, generated by `_measure_presets.py`).

### Ozone Level Meter (`OzoneLevelMeter`)
Renders a **level meter** (peak/RMS history per channel, green/yellow/red,
dB grid, peak-hold line) of the audio as an image — wire the image to
`Preview Image`. The audio passes through unchanged. Modes: Peak, RMS, or both.

The node also embeds a **live view**: after a run, press **▶** inside the node
and the audio plays while an animated peak/RMS meter (with peak-hold line)
scrolls in real time directly in the node. Mute button and time display
included.

### Ozone A/B Compare (`OzoneABCompare`)
Embeds a **player with an A/B switch**: after a run, the two input tracks
(A and B) are loaded into a player widget inside the node. Press **▶**, then
click **Track A / Track B** at any moment — switching happens *during*
playback, instantly and seamlessly (both tracks stay in sync; the inactive
one is muted). Includes play/pause, stop, a seek bar and time display.

The audio output carries track A (or B if A is not connected); the A/B
selection is made with the player buttons in the node.

### Ozone VST Processor (`OzoneVST`) and Parameter Inspector (`OzoneVSTParams`)
Advanced / power-user nodes: any module (including the full `Ozone 12.vst3`
suite, 873 parameters) with JSON overrides, plus a parameter inspector.

## Presets — how it works

- **Raw VST3 state files** (`.vstpreset` / state chunks exported by a DAW):
  loaded natively, 100% faithful.
- **iZotope `.xml` presets** (factory and user): applied *best-effort* by
  mapping the XML parameter names to the VST3-exposed parameters. Parameters
  the VST3 module doesn't expose (e.g. Maximizer *Threshold* / *Margin* in
  some factory presets) are skipped and listed as warnings in the `info`
  output — the preset is never silently half-applied.
- Use `preset_path` (advanced) for a custom file path.

## Why some settings seem to do nothing (and what to do)

Most modules DO process headless — the apparent inertness is usually a
**default value that mutes the effect**, not a missing DSP:

- **Vintage Compressor**: default Ratio ≈ 1.5:1 → threshold alone barely
  compresses. Raise the Ratio (e.g. 4:1–8:1).
- **Unlimiter**: default Amount = 0 → nothing happens until you raise it.
  It also needs pre-limited material to recover dynamics from.
- **Vintage Tape**: default Harmonics/Bias = 0 → Drive alone is subtle. Raise
  Harmonics and/or Bias for real tape saturation.
- **Maximizer**: the limiter Threshold is not exposed by the VST3 at all, so
  on music below 0 dBFS it only does Soft Clip/gains. Use Vintage Limiter.

Genuinely inert modules (verified repeatedly): **Equalizer** (bands don't
respond headless — use Vintage EQ / Dynamic EQ) and **Stem EQ** (needs its
stem analysis).

## Known Ozone quirks handled

- **Full `Ozone 12.vst3` rack state not exposed**: the chain's module
  on/off/order is stored in opaque state, not in parameters, so the full
  plugin only processes its global gains headlessly. `Ozone Global Mastering`
  works around this by chaining the standalone module plugins.

- **Locked/unlocked gain knobs**: Ozone exposes gain controls twice
  (`gain_output_l_locked_db` / `_unlocked_db`) and only one drives the audio,
  depending on internal link state. The node mirrors the value to both, so
  your slider settings always take effect.
- **Stepped parameters**: Ozone params are stepped (e.g. 0.15 dB); slider
  values are snapped to the nearest valid step before being sent.
- **Choice parameters**: params with discrete text values (e.g. EQ band
  shape, soft-clip mode) become dropdowns; setting them no longer errors.
- **Presets vs widgets**: the node applies the preset first, then only the
  slider/toggle values you actually *changed* (values equal to their
  defaults are skipped). Without this, the untouched widget defaults would
  silently reset the preset — presets now keep their sound, and manual
  tweaks still override them. The `Preset On` toggle decides which of the
  two wins: ON = preset (manual ignored), OFF = manual (preset ignored).
- **State leaks between runs**: plugins are cached (loading is slow) and a
  preset/parameter change sticks on the instance. The engine now restores
  every parameter to its factory default (via raw values) before each run,
  so one node's preset can never bleed into another node using the same
  plugin.
- **Widget priority**: each module exposes both a `stereo_main` and an `aux`
  band chain. The node widgets prioritize the global gains and the
  `stereo_main` chain (alphabetical selection used to hide them behind the
  48-widget cap). The full set stays available via `Ozone VST Processor` +
  `params_json`.
- **Non-finite ranges**: params with `-inf` ranges (e.g. Imager *Recover
  Sides Gain*) get a bounded slider instead of breaking the frontend.

## Regenerating the preset measurements

`preset_types.json` (dropdown badges) and `preset_measurements.json` (full
per-band metrics) are generated from the real chain on a reference signal:

```
D:/ComfyUI_windows_portable/python_embeded/python.exe custom_nodes/ComfyUI-Ozone12/_measure_presets.py
```

Takes ~2 minutes for all 331 presets. Re-run it after adding user presets to
`Global Presets` to keep the badges accurate.

## Regenerating the widget cache

Node widgets are built from `param_cache.json` (generated once — instant
startup). Regenerate it after reinstalling Ozone or moving the VST folder:

```
D:/ComfyUI_windows_portable/python_embeded/python.exe generate_param_cache.py
```

## Frontend widgets

The live meter and the A/B player live in `web/ozone_nodes.js` (registered via
`WEB_DIRECTORY`). They receive the audio as a temporary WAV written on
execution (`folder_paths.get_temp_directory()`), so they work without extra
servers. Playback happens in your browser — sound only starts after you press
the play button (browser autoplay policy).

Note: a node only sends its widget payload when it actually executes — make
sure at least one of its outputs reaches an output node (e.g. `Preview Image`
after `Ozone Level Meter`, `Save Audio` after `Ozone A/B Compare`).

## Notes / limitations

- **Licensing**: the plugins must be authorized on this machine (iZotope
  Product Portal / iLok).
- **No GUI**: headless processing only; the AI Master/Track Assistant cannot
  be triggered headlessly (not exposed by the VST3 API) — but you can save
  its result as a preset in the Ozone app and load it via the `preset`
  dropdown.
- **Performance**: plugins load once and are cached (~5 s each, first use
  only); processing is ~0.01 s per second of audio. Cached plugins are
  serialized with a per-plugin lock (thread-safe).
